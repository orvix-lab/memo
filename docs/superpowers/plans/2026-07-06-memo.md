# memo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `@orvix/memo`, an npm-distributed CLI and AI skill for archiving Markdown notes and image attachments into a configured Obsidian vault.

**Architecture:** Node.js owns command routing, i18n, and interactive prompts. POSIX `sh` scripts own deterministic side effects: config persistence, vault validation, note writing, session manifests, platform skill installation, and Git operations. Tests exercise CLI behavior through Node's built-in test runner and temporary HOME/vault fixtures.

**Tech Stack:** Node.js ESM, `@inquirer/prompts`, POSIX `sh`, npm package scripts, Node `node:test`.

## Global Constraints

- Package name: `@orvix/memo`.
- CLI command: `memo`.
- Skill invocation name: `memo` / `$memo`.
- Stable config directory: `~/.config/memo/`.
- Config file: `~/.config/memo/config`.
- Session manifests: `~/.config/memo/state/sessions/`, never inside the Obsidian vault.
- Supported languages for v1: English and Simplified Chinese.
- Supported modes for v1: `local` and `remote`.
- Local mode never performs remote validation, pull, or push.
- Remote mode validates Git worktree, remote, branch, and fast-forward-only pull before writing.
- Commit and push happen only after explicit user confirmation.
- Abandon cleanup deletes only files recorded in the session manifest.
- All note and attachment destinations must be revalidated as paths inside the configured vault.
- The repository currently has no initial commit, so `base-ref` is `null`; verification should fall back to worktree/status checks.
